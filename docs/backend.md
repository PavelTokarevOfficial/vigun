# Backend

`cmd/api` обслуживает REST API, применяет migrations и не запускает тяжёлые операции. `cmd/worker` claim-ит PostgreSQL jobs с `FOR UPDATE SKIP LOCKED` и запускает browser/media adapters.

Основные маршруты: CRUD `/api/streamers`, пакетное добавление ников `POST /api/streamers/bulk`, установка неотрицательного приоритета `PATCH /api/streamers/{id}/priority` с телом `{ "priority": 3 }`, переключение подписки `PATCH /api/streamers/{id}/subscription`, удалённые Twitch clips `/api/streamers/{id}/clips?startedAt=YYYY-MM-DD&endedAt=YYYY-MM-DD` (если даты не переданы — последние 7 дней), импорт в избранное `/api/clips/import`, `POST /api/clips/{id}/download`, presigned preview скачанного источника `GET /api/clips/{id}/source`, `POST /api/clips/{id}/process`, `POST /api/clips/{id}/retry`, `DELETE /api/clips/{id}`, наблюдение за очередью `/api/jobs` и `/api/jobs/{id}`, список готовых рендеров `/api/videos`, потоковое скачивание с `Content-Disposition: attachment` через `GET /api/videos/{id}/download`, inline-поток через `GET /api/videos/{id}/content` и удаление только результата `DELETE /api/videos/{id}`. Для шаблонов есть CRUD, `POST /api/templates/{id}/duplicate` и `PUT /api/templates/{id}/default`; для ассетов — list/upload/rename/move/delete `/api/assets` и CRUD `/api/asset-folders`. Команды enqueue не выполняют тяжёлую работу в HTTP handler: worker забирает созданную job из PostgreSQL.

Подписочная лента отделена от импортированных `clips`: `GET /api/subscriptions` возвращает сохранённые клипы, сгруппированные по подписанным стримерам, `POST /api/subscriptions/{id}/sync` обновляет одного стримера за фиксированное окно в 7 дней, а `PATCH /api/subscriptions/clips/{twitchClipId}/viewed` идемпотентно сохраняет просмотр. Общая кнопка frontend вызывает sync последовательно по одному стримеру, поэтому один HTTP handler выполняет только один ограниченный запрос Twitch, а не длинный пакет всех подписок.

External boundaries: `infrastructure/twitch`, `infrastructure/postgres`, `infrastructure/browser`, `infrastructure/storage`, `infrastructure/ffmpeg`, `infrastructure/whisper`. Подписочный application service зависит только от interfaces `Repository` и `ClipSource`; конкретные PostgreSQL/Twitch adapters собираются в `cmd/api`. Остальной application code использует ports в `internal/processing` и `internal/media`.

S3 adapter не трактует произвольную ошибку как отсутствие файла: `Exists` распознаёт только типизированный S3 `NotFound`/`NoSuchKey` или HTTP 404. Это сохраняет идемпотентность pipeline и не скрывает проблемы сети или credentials.

Конфигурация только через environment variables из `.env.example`. При локальном `cd back && go run ./cmd/api` или `go run ./cmd/worker` приложение автоматически читает `../.env` и заменяет Compose-hostnames `postgres`/`minio` на published `localhost` ports. В Docker имена сервисов остаются без изменений; Docker Compose передаёт свои переменные напрямую, и они имеют приоритет. API не возвращает stack traces или secrets. Повторный импорт существующего Twitch clip оставляет его в избранном и не создаёт download job. Скачивание создаётся только отдельной командой; одновременно для одного clip допускается только один активный job каждого типа. При смене Twitch login cached Twitch user ID очищается и будет заново разрешён перед следующим запросом clips.

Удаление из «Скачанных» проходит через `media.Library`. Если готовых рендеров нет, удаляются все S3-объекты и строка `clips` с каскадной очисткой `media_files` и `processing_jobs`. Если рендеры есть, удаляются только source/audio/subtitle-объекты и их metadata: строка clip и готовые render-ы сохраняются. Нельзя удалить исходник, который сейчас скачивается или обрабатывается. Кнопка удаления в «Готовых видео» использует отдельный endpoint и удаляет только выбранный render object. Если после этого у клипа не остаётся ни исходника, ни рендеров, служебная строка clip удаляется автоматически.

S3 uses two endpoints: `S3_ENDPOINT` is the internal service address used by API/worker, while `S3_PUBLIC_ENDPOINT` is used only to sign browser URLs. In local Docker this is `http://localhost:9000`, not the internal `minio:9000` hostname.

Instagram Reels publishing uses the container flow: `POST /api/videos/{id}/instagram` creates a container, `GET /api/videos/{id}/instagram/{containerID}` reads its processing status, and `POST /api/videos/{id}/instagram/{containerID}/publish` publishes a finished container. The access token and account ID are read only by the API from `INSTAGRAM_ACCESS_TOKEN` and `INSTAGRAM_USER_ID`; `INSTAGRAM_API_VERSION` defaults to `v22.0`. The adapter sends Instagram Login tokens (`IGA...`) to `graph.instagram.com` and Facebook Login tokens (`EAA...`) to `graph.facebook.com`. App ID and app secret are not needed by the publishing calls themselves.

For a local test, expose the frontend (including its `/api` proxy) or API through Cloudflare Tunnel and paste the resulting HTTPS origin into the publish dialog. Instagram then downloads `/api/videos/{id}/content` through the tunnel; the API streams the private MinIO object. Do not replace the host in an existing presigned MinIO URL because its signed `host` would no longer match. The test content route currently has no application authentication, just like the rest of the local API, so the tunnel URL should not be treated as a production access-control design.

Worker получает `SIGINT`/`SIGTERM` через context. Если контекст отменён во время job, job переводится обратно в `pending` с шагом `interrupted`, а не помечается как failed; последующий worker продолжит pipeline с уже сохранённых artifacts.

Worker пишет JSON structured logs для начала, каждого шага (`download`, `extracting_audio`, `transcribing`, `rendering`), завершения, ошибки и длительности job. В полях лога есть `job_id`, `clip_id`, `step` и `progress`.

Пустой результат Whisper сохраняется как допустимый SRT-артефакт, но не передаётся в FFmpeg/libass: render продолжается без слоя субтитров. Если после обрезки временного диапазона конкретного subtitle-слоя в нём не осталось реплик, пропускается только этот слой без fallback на полный SRT. Благодаря этому retry использует уже созданные source/audio/transcription artifacts и не падает на `Unable to open subtitles.srt`.

`POST /api/clips/{id}/process` принимает JSON `{ "templateId": "UUID", "config": { ... } }`. `config` — отредактированная для одного запуска копия шаблона; для совместимости её можно не передавать. API валидирует config, подставляет runtime-значение названия Twitch-канала и сохраняет snapshot вместе с job. Worker скачивает только S3 keys из snapshot во временную папку, строит filter graph из декларативных слоёв и таймлайна и передаёт его в FFmpeg adapter. В HTTP response никогда не попадают credentials или внутренний S3 endpoint.
