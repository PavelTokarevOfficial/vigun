# Frontend

Vue 3 + TypeScript + Vite + Pinia + Vue Router + Tailwind. Код размещён в FSD-каталогах: `app`, `pages`, `widgets`, `features`, `entities`, `shared`.

Сейчас реализованы layout, navigation, CRUD Streamers, пакетное добавление Twitch-ников по одному на строку, изменение неотрицательного приоритета числовым полем и подписка на стримера. Карточка стримера адаптирована под узкий экран: имя, подписка, приоритет и действия располагаются отдельными строками и не создают горизонтальный overflow. Раздел `/search` стал родительским route с двумя вложенными страницами: `/search/subscriptions` и `/search/clips`. Во вкладке поиска сохраняется прежний поиск Twitch Clips по выбранному стримеру и диапазону дат (по умолчанию последние 7 календарных дней) с добавлением результатов в избранное без автоматического скачивания.

Вкладка подписок читает сохранённую недельную ленту и не смешивает её с избранным/Pipeline. Кнопка в строке табов последовательно синхронизирует каждого подписанного стримера. Каждый стример показан отдельной Swiper-каруселью с превью, ссылкой на Twitch, добавлением в избранное и кнопкой «Смотреть клипы». Клик по карточке открывает модалку именно с выбранного клипа, а общая кнопка начинает с первого непросмотренного. Открытый клип сразу получает постоянную пометку «Просмотрено» в карточке и модалке.

Модальный просмотр тоже построен на Swiper. Одновременно монтируется iframe только активного слайда, поэтому соседние клипы не запускаются в фоне. Поверх iframe нет прозрачных drag-кнопок: плеер Twitch полностью интерактивен, а между клипами можно переходить свайпом по информационной части карточки, стрелками под модалкой или клавиатурой. В iframe передаётся текущий hostname как обязательный Twitch `parent`. Twitch требует HTTPS для embed-доменов, поэтому при открытии dev-сервера по HTTP через LAN-IP показывается превью и ссылка на Twitch; рабочий iframe доступен через HTTPS или `localhost`. Добавление стримеров открывается в модальном окне; логика и UI списка находятся в `features/streamer-manager`, а `StreamersPage` остаётся тонкой route-страницей.

Страница `Pipeline` — доска из трёх колонок: «Избранное», «Скачанные» и «Готовые видео». При «В работу» или переносе в третью колонку сначала открывается выбор шаблона, а затем редактор конкретного рендера с предпросмотром скачанного видео. Изменения не сохраняются в базовый шаблон. Job создаётся только по кнопке «Отправить на рендер». Скачанный исходник остаётся во второй колонке после завершения, поэтому его можно удалить вручную или повторно отрендерить другим шаблоном. Ручное удаление исходника скрывает карточку из «Скачанных», но не удаляет связанные готовые рендеры. Каждый успешный рендер показывается отдельной карточкой, даже если один исходник отрендерен несколько раз; на карточке видны шаблон и время создания. Удаление такой карточки удаляет только выбранный render, а не исходный clip и не другие его рендеры. «Открыть» показывает видео в модальном окне, а «Скачать» использует same-origin API с attachment-заголовком и запускает сохранение файла. Отдельной страницы видео нет.

На карточке готового видео есть тестовая публикация Instagram Reels. В модалке вручную вводится HTTPS origin Cloudflare Tunnel, подпись, публикация в ленту и дополнительные поддерживаемые параметры: collaborators, cover URL, thumb offset, audio name и location ID. Фронт создаёт media container, опрашивает его раз в 5 секунд не дольше 5 минут и вызывает publish только после статуса `FINISHED`.

В меню шестерёнки есть страницы «Ассеты» и «Шаблоны видео». Ассеты поддерживают S3 upload, preview, create/rename/move/delete folders и rename/move/delete files. Их операции, состояние диалогов и HTTP-вызовы находятся в `features/asset-manager/model/useAssetManager.ts`; UI загрузки, карточек, модалок и workspace с деревом папок — в `features/asset-manager/ui`. `AssetsPage` — тонкая route-страница, которая только подключает `AssetLibraryWorkspace`. Шаблоны имеют default marker, список, duplicate/delete и editor: очерченная рабочая зона 9:16 на `vue-konva`, реальные image/GIF/video previews, drag/resize, hide, duplicate, undo/redo и свойства слоя. В редакторе конкретного рендера многодорожечный таймлайн показывает монтажную последовательность и все слои шаблона. Фрагменты исходника можно делить, обрезать, удалять и менять местами; video asset выбирается тем же проводником, вставляется в позицию курсора и отображается в списке как «Импортированный контент». Выделение списка, canvas и дорожек синхронизировано, поэтому split/hide/delete работают с выбранным объектом. Есть zoom in/out и «вместить целиком»; блоки слоёв задают время их появления, а canvas переключает источник и позицию видео вслед за курсором монтажа. Элементы в правом верхнем углу canvas локально включают звук и регулируют громкость только активного видео предпросмотра; эти значения не входят в конфигурацию и не влияют на рендер. Финальным источником истины остаётся FFmpeg worker.

FSD используется фактически: `ClipSubscriptionsPage` и `ClipsPage` — тонкие route-компоненты; сценарии загрузки, синхронизации, просмотра и импорта находятся в `features/clip-*`; композиция каруселей, модалки и действий — в `widgets/clip-subscriptions` и `widgets/clip-search`; DTO-типы — в `entities`; общие компоненты/API — в `shared`. Feature-слайсы не импортируют друг друга: совместные действия соединяются на уровне widgets через typed slots и events. Biome форматирует и проверяет frontend: `npm run format`, `npm run lint`; production проверка: `npm run build`.

Карточки «Готовых видео» показывают thumbnail исходного Twitch-клипа. Сам render загружается только при открытии модального просмотра.
