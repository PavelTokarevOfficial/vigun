# Шаблоны и ассеты

Шаблон — это базовая версия JSON-конфигурации композиции, а не строка FFmpeg из браузера. Один шаблон отмечен как используемый по умолчанию. В нём заданы canvas и упорядоченные слои: видео (Twitch-клип или видео-ассет), картинка/GIF, субтитры, текст и блюр. Координаты хранятся в реальных пикселях canvas 1080×1920; редактор показывает уменьшенную копию с реальными выбранными ассетами.

Файлы ассетов находятся в object storage по неизменяемому ключу `assets/{assetID}/original`. Переименование и перемещение меняют только метаданные PostgreSQL. Браузер получает короткую presigned-ссылку, но не получает S3-ключи и учётные данные.

При «В работу» пользователь сначала выбирает шаблон, затем получает его локальную копию в редакторе с предпросмотром скачанного клипа. Эта копия может быть изменена только для текущего рендера. Только кнопка «Отправить на рендер» вызывает API: backend валидирует изменённую конфигурацию и сохраняет в `processing_jobs.template_snapshot` неизменяемый JSON со ссылками на ассеты. Поэтому ни последующее изменение базового шаблона, ни переименование ассетов не меняют ожидающий или выполняемый рендер.

Текстовый слой поддерживает статический текст и значение «название Twitch-канала». Во втором случае application layer подставляет имя стримера в snapshot до постановки job. Блюр компилируется worker-ом как crop текущей композиции, blur, затемнение, прозрачность и обратный overlay в заданную область.

В render editor есть таймлайн на `vue-timeline-editor`. Его сегменты хранят исходные интервалы в секундах. Перетаскивание краёв обрезает интервал, «Разделить» создаёт два соседних интервала, удаление фрагмента исключает его из результата. В snapshot интервалы попадают в `config.timeline`; FFmpeg отдельно trim-ит video/audio каждого интервала и concat-ит оставшиеся части перед композицией.

`Классический vertical` создаётся миграцией как первый шаблон и назначается шаблоном по умолчанию. Старые имена слоёв остаются допустимыми для чтения существующих записей, а frontend нормализует их в новую модель редактора. Старые задачи без снимка продолжают использовать совместимый fallback, пока не будут завершены или удалены.
